## 5. Desktop feature layout (module pattern)

```
src/codeagent/desktop/
├── app.py          # pywebview launcher; injects HTML + DesktopAPI
├── ui.py           # HTML/CSS/JS SPA (all pages)
├── api.py          # JS bridge: thin methods → domain modules
├── models.py       # Ollama/API/mixtures
├── projects.py     # ProjectStore, conversations, files
├── privacy.py      # PRIVACY_VERSION + document (content module)
├── permissions.py, router.py, automation.py, cron.py
├── activity.py, evolution.py, attachments.py, brand*.py
└── __init__.py     # exports DesktopAPI, run_desktop
```

**Pattern:** domain logic lives in sibling modules (`projects.py`, `privacy.py`, …); `api.py` imports them and exposes sync `pywebview.api.*` methods; `ui.py` calls those APIs. Shared agent capabilities stay under top-level packages (`memory/`, `skills/`), not only under `desktop/`.

## 6. Cleanest place for a knowledge-base module

**Recommended:**

1. **Core:** `src/codeagent/knowledge/` (parallel to `memory/` and `skills/`) — store/index, tools (`knowledge_search` / `knowledge_ingest`), optional Obsidian/wiki adapters implementing a small interface (same idea as `MemoryStore`).
